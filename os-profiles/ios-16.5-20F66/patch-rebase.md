# Rebase of the UniXNU XNU patches onto xnu-8796

Status: **complete and verified.** All 59 patches apply strictly, in order,
onto `xnu-8796.101.5` (`aca3beaa3dfbd42498b42c5e5ce20a938e6554e5`). The series
lives in `patches/xnu/`, which `board.toml` selects on its own.

## Outcome

| Result | Count | Note |
| --- | --- | --- |
| carried over unchanged | 54 | context matched exactly |
| hunk re-anchored | 2 | `source-machine-layer` build-config comments; `zzx` pmap split |
| hunk dropped | 2 | the include line they rewrite does not exist in this train |
| patch dropped entirely | 2 | `pgz-aligned-validation`, `published-freezer-condition` |

The two dropped patches patch code that xnu-8796 does not have and that no
other patch in the series creates:

- `pgz-aligned-validation` modifies `zone_id_require_aligned`, which 8796 only
  references inside the `XNU_ZONE_PGZ_ALIGNMENT_PROBE` block. That block is off
  by default and the function has no definition in this train, so there is
  nothing to modify. Enabling the probe on 8796 needs the function ported first.
- `published-freezer-condition` fixes a malformed `#if` in the
  `FREEZE_ENABLED_DEFAULT` block, which does not exist in 8796.

`zzx-pmap-sync-64bit-pa.patch` was split by target. Its
`osfmk/arm64/sptm/pmap/pmap.c` half is dropped because `osfmk/arm64/sptm/` does
not exist in 8796; its `osfmk/arm/pmap/pmap.c` half applies and is kept.

The two prelink patches, `security-init` and `sparse-index`, applied to xnu-8796
without modification. `XnuPrelink` only ships them under `xnu-10063` file
names, so the copies here are renamed `xnu-8796.101.5-*` to name the train they
run on.

## Why measuring in isolation is wrong

A patch in this series can depend on an earlier one creating its target code.
`zone_id_require_aligned` is introduced by `offline-pgz-alignment-probe` and the
freezer block by another patch in the series. Testing a single patch against a
clean `xnu-8796` tree reports "target absent" for both and would wrongly
conclude they are unnecessary.

The series was therefore regenerated by replaying it **in order** against the
8796 baseline, committing after each patch, and taking the per-patch diff. That
is the only way the context of patch N can include the changes of patches
1..N-1.

## Method

```sh
git clone https://github.com/apple-oss-distributions/xnu.git xnu
git -C xnu checkout aca3beaa3dfbd42498b42c5e5ce20a938e6554e5
git -C xnu checkout -b rebase && git -C xnu commit --allow-empty -m baseline

while read -r p; do
  git -C xnu apply --check "/abs/path/patches/xnu/$p" && git -C xnu apply "/abs/path/patches/xnu/$p"
  git -C xnu add -A && git -C xnu commit -m "$p"
done < patches/xnu/series
```

Pass absolute patch paths: `git -C` changes directory first, so a relative patch
name is looked up inside the source tree.

The final gate, run in CI and locally:

```sh
git -C xnu checkout -- . && git -C xnu clean -fd
git -C xnu checkout -B gate aca3beaa3dfbd42498b42c5e5ce20a938e6554e5
while read -r p; do git -C xnu apply --check "$PWD/patches/xnu/$p" || echo "FAIL $p"; done < patches/xnu/series
```

## Where these belong

The shared series own most of these patches:

| Series | Owner | Patches |
| --- | --- | --- |
| `arch:patches/xnu/series` | UniXNU ARM64 profile | the ARM64 set |
| `soc:patches/xnu/series` | UniXNU-sm8550-common | `native-smp-secondary`, `sheng-platform-power` |
| `os:patches/xnu/series` | this OS profile | `zzz-boot-progress` |
| `component:XnuPrelink/patches/` | XnuPrelink | `security-init`, `sparse-index` |

This repository cannot change those, so the rebased copies are duplicated here
and `board.toml` lists only `device:patches/xnu/series`. Upstreaming them and
restoring the four-series `patch_series` is the tidy-up once the shared series
are rebased.
